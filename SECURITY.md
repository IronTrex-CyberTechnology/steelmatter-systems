# Security policy

Steelmatter Systems R0 is a source-only developer preview. It runs locally with synthetic data, synthetic signing keys and a simulated purchase-order destination. It is not a production deployment and must not be used to authorise real purchases (see [NOTICE](NOTICE) and [RELEASE_NOTES.md](RELEASE_NOTES.md)).

We still want to hear about vulnerabilities in its design and code, because R0 is the reference for later releases.

## Supported versions

| Version | Supported |
|---|---|
| R0 source preview (`main`) | Yes, best effort |
| Earlier commits and forks | No |

No binaries or npm packages are published. Fixes land on `main` only.

## Reporting a vulnerability

**Do not open a public issue, pull request or discussion for a security problem.**

Report privately through GitHub: open the repository's **Security** tab and choose **Report a vulnerability** (GitHub private vulnerability reporting). The report is visible only to the maintainers.

Please include:

- the affected component (for example `core/engine`, `core/contract`, `core/auth`, `packages/verifier`, `adapters/mcp`) and commit;
- the invariant or acceptance case it breaks, if known;
- a minimal reproduction using synthetic fixtures only;
- the impact you expect and any suggested fix.

Never include real credentials, personal data or production keys. Use the synthetic keys generated by `scripts/bootstrap`.

## What to expect

- Acknowledgement within 5 working days.
- An initial assessment within 15 working days.
- Coordinated disclosure: we agree a publication date with you once a fix is available, normally within 90 days of the report. We credit reporters unless you ask us not to.


## Scope

In scope, for the source in this repository:

- bypassing exact-action admission, mandate or allowance checks, or placing duplicate orders;
- forging, altering or replaying permits, execution or observation records so that they verify;
- verifier results that report broken evidence as complete or consistent (see [ADR-003](docs/adr/ADR-003-evidence-temporal-linkage.md));
- read or write access beyond the rules in [ADR-002](docs/adr/ADR-002-authorised-readers.md), including cross-tenant access;
- token, authentication or rate-limit bypass in the HTTP API;
- the MCP adapter or SDK letting an agent act outside its assigned actor;
- strict JSON, canonicalisation (RFC 8785) or JWS parsing flaws;
- vulnerable dependencies that are reachable from Steelmatter code.

Out of scope:

- the documented limitations in [RELEASE_NOTES.md](RELEASE_NOTES.md), including the shared database administrators between executor and observer and the accepted CI aggregator limits;
- findings that require an already compromised host, database administrator or trusted signing key, unless the result is evidence the verifier wrongly accepts;
- the synthetic keys, tokens and fixtures committed for testing;
- the simulated destination, the recorded browser demo and the deterministic stand-in agent;
- denial of service by resource exhaustion against a local development instance;
- issues in third-party services or deployments not run from this source.

## Safe harbour

We will not pursue legal action for good-faith research that follows this policy, uses only your own local instance and synthetic data, and gives us reasonable time to respond before disclosure.
